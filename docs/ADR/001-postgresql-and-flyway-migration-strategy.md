# ADR 001: PostgreSQL & Flyway Database Migration Strategy

## Status
Accepted

## Context
InternFlow manages critical educational records, student transcripts, company recruitment opportunities, and formal offers. The database layer must guarantee ACID compliance, transactional integrity, foreign key enforcement, and explicit migration history. Previous iterations had mixed MySQL artifacts; however, production requirements specify PostgreSQL as the sole primary relational database.

## Decision
1. Standardize on **PostgreSQL 16** as the target database engine.
2. Replace all MySQL JDBC drivers and Flyway MySQL plugins with `org.postgresql:postgresql` and `org.flywaydb:flyway-database-postgresql`.
3. Use standard ANSI SQL / PostgreSQL syntax for migrations (`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`).
4. Configure local in-memory fallback using H2 in `MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE` to enable fast, zero-dependency unit and integration tests without requiring Docker or a running PostgreSQL daemon.
5. Provide a production-ready `docker-compose.yml` hosting `postgres:16-alpine`.
6. Enforce `spring.jpa.hibernate.ddl-auto=validate` so Hibernate never auto-creates or alters tables in any environment.

## Consequences
- Guaranteed consistency between migration scripts and runtime schema.
- Eliminated MySQL dependencies entirely.
- Zero external prerequisites needed for running test suites while guaranteeing production PostgreSQL compatibility.
